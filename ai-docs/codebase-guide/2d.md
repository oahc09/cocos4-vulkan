# 2d 模块详解

> 根目录：`native/cocos/2d/` · 规模：~12 文件 · 语言：C++17
> 关联文档：[00-overview](./00-overview.md) · [scene](./scene.md) · [renderer](./renderer.md) · [core](./core.md) · [ui](./ui.md)

## 1. 模块职责与定位

`2d` 模块负责 **2D / UI 元素的批处理渲染**，是 Cocos UI 系统在原生侧的渲染后端。它把 JS 侧大量 UI 渲染对象（Sprite、Label、Graphics、Mask 等）合并为尽量少的绘制批次（draw call），并处理遮罩（Stencil）裁剪，最后产出 `scene::DrawBatch2D` 交由渲染管线的 UI 阶段提交。

核心定位：
- **批处理（Batching）**：`Batcher2d` 遍历 UI 节点树，按材质/纹理/层级/遮罩状态合并顶点，减少 draw call。
- **顶点缓冲管理**：`UIMeshBuffer` 管理 CPU 侧顶点/索引数组与 GPU `InputAssembler` 的映射与上传。
- **渲染数据载体**：`RenderEntity` / `RenderDrawInfo` 是 JS 与 Native 共享内存的轻量结构（含 `static_assert` 尺寸约束，避免缓存行放大）。
- **模板遮罩**：`StencilManager` 以单例维护 UI Mask 组件的模板测试阶段栈。
- **Graphics 代理**：`UIModelProxy` 把 `Graphics` 的几何数据代理为可渲染 `scene::Model`。

> 与 [ui](./ui.md) 区分：`2d/` 是引擎**自绘**的 UI 渲染；`ui/` 是系统**原生控件**（输入框/视频/网页）的桥接，二者不在同一层。

## 2. 目录树与子目录说明

```
2d/
└── renderer/
    ├── Batcher2d.h/.cpp        # 2D 批处理器（核心）
    ├── RenderEntity.h/.cpp      # 渲染实体（UI 对象数据载体）
    ├── RenderDrawInfo.h/.cpp    # 单次绘制信息（顶点/索引/材质/纹理）
    ├── UIMeshBuffer.h/.cpp      # UI 顶点/索引缓冲管理
    ├── StencilManager.h/.cpp    # 模板遮罩状态管理（单例）
    └── UIModelProxy.h/.cpp      # Graphics → scene::Model 代理
```

> 模块规模小但全部位于 `2d/renderer/`，均由 `Batcher2d` 统一驱动；平台无关，最终产出 `scene::DrawBatch2D`（见 [scene](./scene.md)）。

## 3. 关键类 / 结构体

| 类 / 结构体 | 关键成员（真实签名摘要） | 职责 |
| --- | --- | --- |
| `Batcher2d` | `walk(Node, parentOpacity, parentColorDirty)`、`fillBuffersAndMergeBatches()`、`generateBatch()`、`uploadBuffers()`、`getMeshBuffer(accId, bufferId)` | 批处理器：遍历节点、合批、生成 `DrawBatch2D`、上传缓冲 |
| `RenderEntity` | `RenderEntityType _renderEntityType`、`getIsMask()`、`getOpacity()`、`addDynamicRenderDrawInfo()`、`EntityAttrLayout _entityAttrLayout` | UI 渲染实体：`Node::UserData`，承载 `RenderDrawInfo`（静态联合数组容量 4 / 动态 vector） |
| `RenderDrawInfo` | `RenderDrawInfoType _drawInfoType`、`setMaterial()`、`setMeshBuffer()`、`requestIA()`、`updateLocalDescriptorSet()` | 单次绘制信息：顶点/索引偏移、材质、纹理、Sampler、IA |
| `UIMeshBuffer` | `setVData()/setIData()`、`uploadBuffers()`、`requireFreeIA()`、`parseLayout()`、`MeshBufferLayout` | UI 缓冲：CPU 侧 `vData`/`iData` 与 GPU `vb`/`ib`/`ia` 的映射 |
| `StencilManager` | `getInstance()`、`enterLevel()`、`exitMask()`、`getDepthStencilState()`、`getStencilRef()` | 模板遮罩单例：维护遮罩层级栈与 `DepthStencilState` 缓存 |
| `UIModelProxy` | `initModel(Node)`、`uploadData()`、`activeSubModels()` | Graphics 代理：把图形顶点代理为 `scene::Model` 子模型 |

`Batcher2d` 默认顶点属性（见 `_attributes`）：`position(RGB32F)`、`texCoord(RG32F)`、`color(RGBA32F)`；遮罩模型使用仅 `position` 属性。`MeshBufferLayout{ byteOffset, vertexOffset, indexOffset, dirtyMark }` 描述缓冲布局，`Render2dLayout{ position, uv, color }` 为组件绘制布局。`UIModelProxy` 使用另一组属性：`position(RGB32F)`、`color(RGBA32F)`、`a_dist(R32F)`（用于 `Graphics` 距离场描边），图元模式 `TRIANGLE_LIST`，stride 32 字节。

遮罩阶段流转：`StencilStage` 从 `DISABLED` 起，遇到 Mask 实体依次 `CLEAR`→`ENTER_LEVEL`（普通）或 `CLEAR_INVERTED`→`ENTER_LEVEL_INVERTED`（反向），内容绘制期保持 `ENABLED`，退出时 `EXIT_LEVEL`；`StencilManager::getWriteMask()`/`getStencilRef()` 按 `_maskStackSize` 位运算生成模板写掩码与参考值，`_currStencilStage` 初始 `DISABLED`。合批时若 `MaskMode` 或 stencil 阶段变化，必须打断批次并切换 `DepthStencilState`（取自 `StencilManager::getDepthStencilState()` 缓存）。

`Batcher2d` 主流程方法：`syncRootNodesToNative()` 接收根节点 → `walk()` 递归遍历 → `handleComponentDraw()/handleModelDraw()/handleMiddlewareDraw()/handleSubNode()` 分类处理 → `generateBatch()` 合批 → `uploadBuffers()` 上传 → `fillBuffersAndMergeBatches()` 合并批次。遮罩相关：`insertMaskBatch()`、`createClearModel()`、`_maskClearModel`（清空模板的专用模型）。`RecordedRendererInfo` 队列支持 UI 渲染器的延迟录制与 `flushRecordedUIRenderers()`。

## 4. 关键枚举 / 常量

```cpp
// RenderEntity.h
enum class RenderEntityType : uint8_t { STATIC, DYNAMIC, CROSSED };
enum class MaskMode : uint8_t { NONE, MASK, MASK_INVERTED, MASK_NODE, MASK_NODE_INVERTED };
enum class FillColorType : uint8_t { COLOR = 0, VERTEX };
// EntityAttrLayout 大小约束（缓存友好）
static_assert(sizeof(EntityAttrLayout) == 12, "...");
static_assert(sizeof(RenderEntity) == 640, "..."); // x86_64/aarch64

// RenderDrawInfo.h
enum class RenderDrawInfoType : uint8_t { COMP, MODEL, MIDDLEWARE, SUB_NODE };
static_assert(sizeof(RenderDrawInfo) == 144, "...");

// StencilManager.h
enum class StencilStage : uint8_t {
    DISABLED=0, CLEAR=1, ENTER_LEVEL=2, ENABLED=3,
    EXIT_LEVEL=4, CLEAR_INVERTED=5, ENTER_LEVEL_INVERTED=6
};
```

`Batcher2d` 默认属性与遮罩模型属性为编译期常量数组；`StencilManager` 的写掩码按 `_maskStackSize` 位运算生成（`getWriteMask()` = `1 << (_maskStackSize-1)`）。

## 6. 与上下层交互

- **上游（core / bindings / ui）**：JS UI 组件通过 `bindings` 共享内存写入 `RenderEntity`/`RenderDrawInfo` 的 `vData`/`iData`（经 `NativeMemorySharedToScriptActor`）；`Batcher2d::walk()` 从根节点（`syncRootNodesToNative()`）递归遍历 `core::Node` 树。
- **下游（scene / renderer / pipeline）**：合批结果写入 `scene::DrawBatch2D`（`_batches` 使用对象池 `memop::Pool<scene::DrawBatch2D>`），最终经管线的 UI 阶段提交；`DrawBatch2D::fillPass()` 填充 `Material`/深度模板状态/宏补丁，复用 `scene::Pass` 与 `gfx::Shader`。
- **遮罩**：`StencilManager` 在 `handleUIRenderer` 流程中根据 `MaskMode` 调整 `StencilStage`，影响 `DrawBatch2D` 的深度模板状态（见 `RenderEntity::getIsMask()`）。
- **Graphics**：`UIModelProxy` 把矢量图形代理为 `scene::Model`，走与普通 3D 模型相同的 `SubModel`/`Pass` 绘制路径。

**典型数据流**：JS UI 组件每帧写入 `RenderEntity`/`RenderDrawInfo` 的共享内存（`vData`/`iData`）→ `Batcher2d::walk()` 从根节点递归遍历 `core::Node` → 按材质/纹理/层级/遮罩状态 `generateBatch()` 合批，写入 `UIMeshBuffer` → `uploadBuffers()` 上传顶点/索引到 GPU `ia` → 产出 `scene::DrawBatch2D`（对象池 `memop::Pool`）→ 管线 UI 阶段按 `StencilManager` 提供的深度模板状态提交。`EntityAttrLayout`（12 字节）紧凑打包 priority/color/maskMode/fillColorType 等位域，配合 `static_assert` 控制 `RenderEntity`(640)/`RenderDrawInfo`(144) 尺寸以优化缓存。

## 7. 修改 / 扩展要点

1. **新增 UI 组件绘制类型**：扩展 `RenderDrawInfoType`（COMP/MODEL/MIDDLEWARE/SUB_NODE）或 `Batcher2d::handleXxxDraw()`；注意 `RenderDrawInfo` 尺寸有 `static_assert(==144)`，新增成员需重新核对缓存行。
2. **合批规则调整**：在 `fillBuffersAndMergeBatches()`/`generateBatch()` 中修改打断批次的条件（材质哈希 `_currHash`、纹理、层级、遮罩阶段）；合并的前提是相同属性布局与相同 Pass。
3. **顶点属性扩展**：默认属性在 `Batcher2d::_attributes`，遮罩在 `_maskAttributes`；新增属性需同步 `UIMeshBuffer::initialize()` 与 `parseLayout()` 的 stride 计算。
4. **内存与生命周期**：`UIMeshBuffer` 的 `vData`/`iData` 可能为 JS 共享内存（弱引用），由 `_needDeleteVData` 标记是否 Native 拥有；`RenderEntity`/`RenderDrawInfo` 在 Native 侧多为手动管理或池化，勿随意 `IntrusivePtr` 持有 JS 共享对象。
5. **性能敏感路径**：`walk()` 为每帧热点，避免在其中分配；`UIMeshBuffer` 的 IA 通过 `requireFreeIA()`/`recycleIA()` 复用，`dirtyMark` 控制上传范围。改动后建议对照 [04-pipeline-deep-dive](./renderer.md) 确认 UI 阶段提交无误。
6. **中间件（Middleware）路径**：`handleMiddlewareDraw()`/`generateBatchForMiddleware()` 服务于富文本/自定义渲染中间件（如 `Label` 的 BMFont/系统字体排版结果），其 `iData` 来自中间件而非组件共享缓冲，注意 `_currMiddlewareIbCount` 的计数与 IA 创建分支。
7. **遮罩与层级**：`MaskMode`（MASK/MASK_INVERTED/MASK_NODE/MASK_NODE_INVERTED）决定 `RenderEntity` 是否进入模板栈；`StencilManager::getStencilHash()` 以 `(stage<<8)|_maskStackSize` 作为状态缓存键，修改遮罩语义后需确认 `DepthStencilState` 缓存不会串状态。
8. **对象复用与缓存**：`Batcher2d` 用 `memop::Pool<scene::DrawBatch2D> _drawBatchPool` 池化 `DrawBatch2D`，避免每帧分配；`releaseDescriptorSetCache(texture, sampler)` 释放按纹理/Sampler 缓存的描述符集；`getMeshBuffer(accId, bufferId)` 通过 `UIMeshBufferMap`（按 accId 分组的数组）复用 `UIMeshBuffer`。改动回收逻辑时务必与 `reset()` 配合，防止跨帧悬挂引用。
