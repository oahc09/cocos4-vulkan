# 2026-07-24

## 结合 Vulkan 近年演进（1.3/1.4/Roadmap2026）给 Cocos Vulkan 后端改进建议

- **事实基线（已 WebSearch 核实，2026-07）**：
  - Vulkan 1.4 于 2024-12 发布并纳入核心：dynamic_rendering_local_read、synchronization2、push descriptors、scalar block layouts、host image copy（可选）、pipeline robustness（VK_EXT_pipeline_robustness→core）、maintenance6。**注意 graphics_pipeline_library 仍是 EXT（VK_EXT_graphics_pipeline_library，2022），未进 1.4 核心**，需显式开启。
  - Vulkan Roadmap 2026（2026-01-23）发布：强制 VRS（引擎已用 VK_KHR_fragment_shading_rate）、shader clock、host image copy、compute shader derivatives、swapchain 改进、更高描述符/接口上限；并引入 **VK_EXT_descriptor_heap**——全新描述符体系、直接访问描述符内存，意图**完全取代现有描述符集**；**VK_EXT_descriptor_buffer 已被其废弃**（Khronos registry 标注 "Deprecated by VK_EXT_descriptor_heap"）。
  - **Vulkan 1.5 截至 2026-07 不存在**；最新为 1.4 + Roadmap2026 里程碑。
  - VK_EXT_device_generated_commands（DGC）为 EXT（2024-02，需 1.1+buffer_device_address），仍是 EXT 非 KHR；Valve/Zink 采用，GPU 生成命令缓冲，indirect draw 的现代继任者。
  - Khronos 现已主动标记废弃（deprecation 机制）：debug_marker→debug_utils；descriptor_buffer→descriptor_heap。

- **与现有代码缺口（已 grep 核实）的映射**：
  - 无 pipeline cache（VKPipelineState.cpp:43-67→VKCommands.cpp）→ P0 用 VK_EXT_graphics_pipeline_library + cache（比"只加 VkPipelineCache"更现代，编译拆为可链接阶段，首帧卡顿转异步/并行）。
  - 帧末 vkWaitForFences 阻塞整帧（VKDevice.cpp:716-717/745）→ P0 用 VK_KHR_timeline_semaphore（1.2 核心，仅开 requestedVulkan12Features.timelineSemaphore）。
  - 无 dynamic rendering（render-pass 对象）→ P1 用 1.4 核心 dynamic_rendering + local_read（连 input-attachment 类效果也脱离 render pass）；需隔离 RenderPassStrategy（前次建议）。
  - 无 synchronization2 → P1 1.3 核心 VkPipelineBarrier2，引擎已带 thsvs_simpler_vulkan_synchronization.h 可直接接。
  - 无 bindless/descriptor indexing 启用 → P1 用 1.2 核心 descriptor indexing；前瞻用 VK_EXT_descriptor_heap（取代此前建议的 descriptor_buffer，后者已废弃）。
  - VK_EXT_debug_marker（VKDevice.cpp:127，仅 CC_DEBUG）→ 迁移 VK_EXT_debug_utils（实例扩展），改善 RenderDoc/PIX 对象命名/标签（caosh 用 RenderDoc）。
  - Swappy 已用（CC_SWAPPY_ENABLED）→ 加 VK_KHR_present_wait/present_id 做帧节奏/延迟控制。
  - Profiler → VK_KHR_calibrated_timestamps（GPU/CPU 时间戳对齐）+ Roadmap2026 shader clock。
  - 移动端/UMA 流式上传 → 1.4 host image copy（可选支持）减轻 staging/transfer 争用（关联 CCVKGPUStagingBufferPool）。
  - 移动端瓦片 GPU → VK_EXT_subpass_merge_feedback 自动 subpass 合并。

- **优先级与权衡**：
  - 引擎已协商到平台最高版本（RTX 4060 上即 1.4）；动作=开 feature bit + 加扩展请求（VKDevice.cpp:122-136 / :149 / :233-236），不是改版本协商。
  - 最低规格风险：1.4 在部分老移动 GPU 未达；保留 1.2 回退，全部 capability-gated + 优雅回退。
  - 建议顺序：P0（pipeline library+cache、timeline_semaphore）→ P1（1.4 核心：dynamic_rendering+local_read、sync2、push descriptors、host image copy、pipeline robustness）→ P2（Roadmap2026：descriptor_heap、present_wait、calibrated_timestamps、shader clock）→ P3（DGC、mesh shading、ray tracing、subpass_merge_feedback）。
